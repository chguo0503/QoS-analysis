# Baseline 与带宽感知 FIFO 对照实验

## 实验口径

- 共同拓扑：64 GPU，SSD 数量从 1 扫描到 10，每块 SSD 前有独立 QoS。
- 共同负载：每张 GPU 执行 1 次推理的第 0 层；Token 数在 100K–200K 间采样，命中率在 50%–99% 间采样。
- 共同放置/绑定：KV Block 稳定随机放置；DPU 使用 `random_sticky`，即一个 `(GPU, SSD)` 稳定绑定一个 Queue。
- 共同调度：Group WRR 和 Queue WRR 的权重全部为 1。
- baseline：关闭 DPU 速率控制，所有 Queue `CIR=0` 且 `PIR=uncapped`。
- 带宽感知 FIFO：DPU 用整数 Byte/s 读取需求，容量足够时设置有限 `CIR=PIR=需求`；过载时不缩放已准入速率，后到需求留在 Queue 中等待。
- 后端：使用详细 ASU SSD 离散事件模型，每块 SSD 的 NAND 上限为 40 GB/s。

> 图表中的 TTFT 是“仿真 1 层”的结果。该口径用于完成 64 GPU × 10 种 SSD 数量 × 2 种策略的详细后端扫描，不能直接乘以 78 充当完整模型 TTFT。

## 为什么带宽感知 FIFO 反而更差

### 1. Queue 碰撞破坏了需求隔离

64 个 GPU 虽然面向 256 个 Queue，但 `random_sticky` 仍允许多个 GPU 绑到同一 Queue。SSD=1 时只使用了 58 个不同 Queue，有 6 个 GPU 是碰撞 Queue 中的后到者。

当两个需求共享一个 Queue 时，DPU 会把两份已准入速率相加成 Queue 速率，但 Queue 内部只有一条 FIFO。先到需求会使用两份速率先排空自己的 IO，后到需求却必须等它通过；Queue 无法按 demand ID 隔离两份预留。

- SSD=1–10 时，“GPU 作为同 Queue 后到者的路径数”与 TTFT 退化的相关系数为 0.697–0.784。
- SSD=2–10 时，没有后到碰撞的 GPU 平均只比 baseline 慢 0.06–0.08 ms。
- 发生一次后到碰撞的 GPU 平均多等待约 218–317 ms；发生两次或更多时，平均多等待约 417–464 ms。

### 2. 多 SSD 的层屏障放大了碰撞

一层的 Block 随机分布到多块 SSD，GPU 必须等最后一个 Block 完成。SSD 越多，一张 GPU 在至少一条路径上成为后到碰撞者的概率越大：SSD=1 时有 6 个这类 GPU，SSD=10 时已有 39 个。层完成时间由最慢路径决定，所以路径数增加反而放大了问题。

### 3. `PIR=CIR` 不是 work-conserving

baseline 的 uncapped Queue 可以立即借用所有空闲后端容量，并由 SSD 的 40 GB/s 物理上限实际限速。当前 FIFO 对已准入 Queue 设置 `PIR=CIR=诉求`，不允许它使用其他需求暂时未使用的份额。这保持了简单有限速率，但不会自动提高总利用率。

## 真正过载的高命中率压力组

为了确认 FIFO 过载语义，另外使用 90%–99% 命中率运行 SSD=1–3。这组有 66,180 个 IO，总聚合诉求约为 87.782 GB/s；因此 1 块和 2 块 SSD 过载，3 块 SSD 容量足够。

这组证明新逻辑确实按设计运行：预留从未超过 40 GB/s，也没有对已准入 CIR/PIR 做比例缩放；超过容量的后到需求保留在 Queue。

SSD=1 时，初始准入前 26 个需求，预留约 36.94 GB/s，后 38 个需求等待。前 26 个 GPU 相对 baseline 平均快约 50.1 ms，后 38 个 GPU 平均慢约 44.5 ms。这说明严格 FIFO 优化的是“先到者优先”，不是全局平均、P95 或公平性。

## 结论与下一步

当前带宽感知 FIFO 在所有已测点都没有超过 baseline。核心原因不是整数速率误差，也不是旧的比例缩放；而是“随机 Queue 碰撞 + 单 FIFO 无法隔离多个 demand + 多 SSD 层屏障”。

最值得下一步对比的策略是：

1. 每个活跃 demand 优先租用一个空 Queue，结束后释放；本实验每盘只有 64 个 GPU、256 个 Queue，完全有条件避免碰撞。
2. 只在无空 Queue 时退化为最小 Queue depth 或 FIFO 等待；该决策只需要整数计数和比较。
3. 保留 `CIR=需求`，但可将已准入 Queue 的有限 PIR 设为 SSD 物理上限，使空闲容量可被借用；后到过载 demand 仍由 `qos_admitted=false` 阻止，不需要浮点运算或比例缩放。

这样才能把“带宽诉求感知”转化为可测量的收益，而不是先被 Queue 绑定碰撞消耗掉。
